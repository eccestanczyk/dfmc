# Asset optimisation — the rule for every image the game ships

Written July 2026 after a load-performance audit found the game pulling **23 MB of images per
fresh session** to paint a screen that needs about 1.5 MB. Read this before adding ANY new
raster asset, and before pointing the client at one.

## The three budgets

| budget | limit | why it bites |
|---|---|---|
| **Decoded memory** | ~150 MB desktop, ~80 MB mobile | An image costs `width x height x 4 bytes` in RAM **regardless of file size**. A 65 KB WebP at 512x512 occupies 1 MB. Holding the whole catalogue would be ~2 GB. |
| **Transfer per session** | keep under ~2 MB for a cold start | raw.githubusercontent sends `cache-control: max-age=300`. jsDelivr sends a week. |
| **Repo storage** | soft, we have room | Derivatives are small; the originals are the expensive part and they stay. |

Memory is the one that actually binds. It is set by PIXEL DIMENSIONS, not by how well the file
compresses, which is why "just use WebP" is not a substitute for resizing.

## The rule

**Author every derivative at 2x the largest box the asset is ever painted into, capped at the
original's own size.** 2x covers retina; beyond that nobody can see the difference and you are
paying for it in RAM on every device.

Before adding an asset, find its box in `play/markup.html` (the `width:Npx; height:Npx` on the
element that paints it) and size from that. If an asset is painted at several sizes, use the
largest. Never size from "what the art looks like at 100%".

## How it is wired

- Originals live where they always did and are never touched. They are the master for re-exports.
- Derivatives are generated by `tools/make_derivatives.py` into a parallel `opt/` path.
  Run it after adding art; it skips anything already current.
- The client points at the derivative. `TARGETS` in that script is the single list of what gets
  optimised and at what size — add a row there rather than converting by hand.
- Local UI art (the client's own `play/img/`) is WebP at source dimensions, except where a small
  paint box is confirmed, in which case it is resized to 2x that box.

## Serving

**Everything goes through jsDelivr, never raw.githubusercontent.** raw sends `max-age=300`, so
those assets re-download most sessions; jsDelivr sends `max-age=604800` plus edge caching. If you
add a URL helper in the client, base it on `CDND`, not `RAWD`.

## Preloading — scope, not catalogue

Preload the **one-step closure of the current state**, never the catalogue. Tiers:

| tier | when | what | cost |
|---|---|---|---|
| 0 shell | blocks the loading veil | logo, UI frames, status papers | ~10 MB |
| 1 floor | on entering a floor | plate + the 10 pool spawns (+ mutant variant when the spawn is flagged) | ~18 MB |
| 2 battle | before the intro veil lifts | the 6 combatant sprites + the status icons every equipped move can apply | ~6 MB |
| 3 idle | after boot, never blocking | icons for what is IN THE BAG, thumbs for OWNED creatures | ~4 MB |

Never preload other zones' plates, unowned creatures, or unequipped item art. Hold `Image` refs
in a warm map so the decode is retained — dropping the ref lets the browser evict the decode and
the asset pops in again on next paint.

## What "already fine" looks like

Not everything needs work. These were audited and left alone:

- `codex/thumbs/creatures/silhouette` — 300 files, 128x128, 3 KB each. Correct by construction.
- `codex/images/med` — 512x512 at 65 KB for a 110-128px box. 4x linear, but cheap, and the extra
  resolution shows during the scale-up flourishes.
- `floors/ground_plates/1080` — authored at exactly the 1920x1080 stage size, which is right.
  (The client used to paint them at `background-size:132%`, upscaling 1.32x and cropping 43% of
  each image away. That was fixed to `100% 100%` so they render 1:1.)

## Checklist for a new asset

1. Find the paint box in the markup.
2. Add a row to `TARGETS` in `tools/make_derivatives.py` at 2x that box.
3. Run the script; commit the original AND the derivative.
4. Point the client at the derivative through a `CDND`-based helper.
5. If it appears in a scene that must not pop, add it to the right preload tier.
