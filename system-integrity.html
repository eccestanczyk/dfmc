SAVE, ECONOMY & ANTI-CHEAT

Other Systems › Save, Economy & Anti-Cheat

One doctrine underneath everything: the client sends events and requests, never state. The local save is a disposable prediction cache, overwritten on every server reconciliation — editing it is inert, not forbidden. This page is the distilled, validated summary; the full technical spec is SAVE_ARCHITECTURE.md (v2).

The transaction contract

Every economic action is: check server balance → atomic debit + grant → or reject whole. Nothing partial, nothing client-computed. Two mechanisms make "atomic" real rather than aspirational:

MechanismWhat it stops
Idempotency keysEvery request carries a unique key; replays of the same request are no-ops. Retried packets and deliberate double-sends cannot double-grant.
Version tokens (write locks)Cloud Save writes are compare-and-swap on a version token. Two simultaneous spends that both read balance 100 cannot both commit — the second fails and re-reads. This is the actual historical dupe vector: Diablo 3's trillions-of-gold incident was a transaction-layer race in its own auction house, not a hacked client.

Reward path & the accrual cap

The client reports what happened (battle event logs); the server derives reward values from its own tables — a client cannot name a number. On top of that sits the single cheapest, strongest control an autoplay game can have:

Wall-clock accrual cap. Rewards credited per flush are capped by elapsed real time (~30 battles/hour at autoplay pace, with headroom). A client claiming 4,000 battles in ten minutes is not investigated — it is arithmetically impossible and clipped at the ledger. Farming faster than time permits cannot be expressed in the protocol.

Verification — trust, but replay

EventVerification
Boss kills, floor/ladder advances100% seeded-replay verified: the server issued the encounter seed, the client submits the move log, Cloud Code re-simulates deterministically and compares the claimed result. Value-gating events are never taken on faith.
Ordinary grind battlesRandom sampling + statistical invariants: monotonic XP, battle-rate plausibility, streak-threshold consistency, drop-rate bounds, currency reconciliation. Cheap to run, expensive to fool at scale.
Rated PvP matchesEvery match ends with one deterministic replay adjudication — full spec on PvP, Timers & Persistence (team legality by recompute-from-inputs, commit–reveal rounds with reveal-derived RNG seeds, per-round state checksums, replay as final authority).

The residual threat: farm accounts

Once client cheating is inert, the economy's remaining attacker plays legitimately — fleets of accounts running real autoplay to print tradeable items. Mitigations, in order:

GateEffect
Steam's $5 limited-account gateMarket and trading are locked behind Steam's own spend threshold — each farm account has a real cost floor.
Progression-gated market unlockTrading unlocks only past a progression milestone; a farm account must invest real climb-time before it can sell anything.
Listing velocity monitoringAccounts whose listing rate is inconsistent with their play pattern get flagged for the audit queue — the CS:GO key-fraud lesson: watch the exit, not just the faucet.

Leaderboards are server-derived (ANTICHEAT 2, 2026-07-30)

The studied model is Steam's Trusted writes: leaderboard scores cannot be set by clients — only the publisher's own server may write them. Client-writable boards die predictably (every Papers, Please endless board tops out at a forged 2,147,483,647). Herumon Tower follows the same rule: /api/lb/submit is retired (HTTP 410) and no client-callable board write exists. Every board value is derived from truth the server already owns:

BoardSource of truthWrite policy
ladderThe server-owned Elo. Folded from the ratings table once per snapshot day, at the board's own recut — finish-time board writes were removed the same day (D ruling): the board read is daily anyway, so per-match freshness was invisible and cost a write per match. Ratings live in the world object, so the fold is a bounded in-object pass over pvp-active players; unchanged rows bill nothing.set — the ladder shows the current rating; the row's first-arrival timestamp is kept.
climbThe maxFloor ratchet (progress), advanced only by credited battles. When a battle ratchets, the player object annotates its response and the Worker relays the new value to the world object under waitUntil — objects never call objects, and the player's response is never delayed.max — keep-best; monotone by construction. ~1 write per floor per player lifetime.
powerThe one value with no server recompute yet (that is ANTICHEAT 5). It rides the save as pw, is stripped from the stored record, and is validated in the player object against POW_MAX = LB_POW_BASE + LB_POW_PER_FLOOR × (ratchet+1) (env-tunable; defaults 2,000 + 1,500×f, calibrated from live data: 3,380 power at maxFloor 5 → ~3× headroom).max — keep-best, deadbanded (only an improvement over the last published value is relayed, so a 10-second autosave cadence can never become a world-write cadence). The climb ratchet also rides the save the same way, so accounts whose progress predates the boards appear at the flip instead of waiting for their next advance; the world's keep-best absorbs the one redundant publish after each battle-side advance.
  • Breach = quarantine, never clamp. A power claim over the ceiling is flagged (lb_power_over) and writes no row — a cheater is absent from the board, never parked at the ceiling — and the save itself is stored untouched.
  • The first-there tiebreak is unforgeable: at is stamped by the server at the moment of the improvement. The retired submit route accepted a client at, which let a forged at:1 win every tiebreak forever; that class of input no longer exists.
  • A lower value never erases a stored best (the retired route's INSERT OR REPLACE could).
  • Rider, same batch: a battle event's floor is now clamped to ratchet+1 before it prices kills or advances anything (battle_floor_over flag). A forged floor-50 event used to ratchet — and would have boarded — 50 floors in one request; clamped, a fake climb costs one credited battle per floor through the spawn budget and rate caps, the same cost class as playing. The full enter-proof (require the floor's floors_srv row) stays on the Phase-2b list.
  • Reads are unchanged: the daily lb_snap top-100 behind a 30-minute edge cache, the daily rank pass for exact ranks, and /api/lb/purge as the removal tooling.
  • Board display names come from the world name/claim identity (claimed at character creation); an account without one shows Climber.

Failure & cost doctrine

Precedent says the model holds: the mobile-strategy pattern this follows (client as pure view, all authority server-side) is why modded clients achieve nothing against such games. Its known failure modes are the transaction layer (handled above) and cost blowout — the naive build of this same architecture (UGS Economy ledgers, per-round PvP server resolution) priced at >$450k/month at 500k CCU; the committed build lands at ~$0.02–0.03 per concurrent user per month (~$12–15k/month at 500k CCU), dominated by batched Cloud Save writes. Flush tiers: immediate for stakes (deaths, trades, ladder), batched for grind accrual.
