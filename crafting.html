CRAFTING

Nothing is useless. Every drop dismantles into materials. Every material crafts the next tier.

Recipes are authored, not formulaic. Every craftable item has its own row in codex/recipes.csv with an explicit material bill. There is no cost formula anywhere in the crafting system — change a recipe by editing its row. Output grade defaults to Worn — the forge can deliver up to Rare for a surcharge derived from the grading ladder at the recipe's tier (2026-07-31), so forging is never cheaper than grading it yourself; the climb beyond is the separate Scrap-fed gamble on the Upgrading page.

Raising an item's grade

There is no combining. Gear grade is raised only by spending resources on an attempt — Scrap for gear, Dust for gems, Essence for runes, Ink for scrolls, all authored in codex/grading.csv at the item's tier (360 tier-scaled rows, 2026-07-31). A failed attempt consumes the currency and leaves the item exactly as it was; nothing is ever destroyed. Those are the same resources dismantling yields, so every drop feeds the ladder. See the Upgrading page for the full table.

Scroll rerolling

There is no separate reroll action and no Ink cost. Applying another scroll over a socketed one is the reroll — it draws a fresh class and value from codex/enchants.csv, and the enchantment it replaces is destroyed. Scrolls can never be unsocketed; gems and runes always return to the bag intact.

Scroll legality (2026-07-31): a scroll is a die, not a fixed stat — the socket stat-match rule judges its rolled result. A flat Attack/Defense/HP roll must match the host stat exactly like a gem; item-local % rolls are host-relative by definition, and Increased/More/utility rolls and unrolled scrolls fit any host. (Before this ruling the catalog text was unreadable as a stat, so every socketed scroll in the game read ILLEGAL — bug #3.)

Socket identity (2026-07-31): every equipped item is its own instance — two copies of the same item never share sockets. Unequipping or swapping an item returns its gems and runes to your bag (D ruling 2026-07-31); only the scroll stays bound to the item, travels with it, and returns to its socket when the item is equipped again. Dismantling a socketed item refunds its gems and runes the same way — the scroll is destroyed with it. Promoting an equipped item carries only that copy’s scroll across the grade.

Mutants are never dismantled

D order 2026-08-21 (LIVE on release since 2026-08-21 (0.58)): every dismantle door refuses a Mutant creature (cat Monster with mut:true). One shared gate does it — dismYield returns null for a Mutant, the same mechanism that protects class souls — so every door is covered without its own check: the creature sheet withholds its DISMANTLE button, the hammer refuses the mark with “MUTANT — mutants are never dismantled” (never the generic no-salvage toast, which would hide the reason), “by grade” and “all filtered” sweeps skip them, Adam and Eve treats them like levelled creatures — neither dismantled nor a bucket’s keeper, spared not favoured, and its window says how many it is leaving — and execDism’s final filter pays nothing for one even if a stale reference forces it into the marked list. The ops door POST /api/backup/dismantle carries its own copy of the refusal, because it is the one dismantle that runs server-side without the client’s gate.

The server keeps paying a Mutant claim on purpose. src/dismantle.js — the Worker’s pricing copy — deliberately does not carry the refusal: a stale release client that still dismantles a Mutant must have its claim verify and pay (additive-only backend rule), and withholding pay would protect nothing anyway — the destruction happens client-side, so the protection lives client-side. The parity suite pins this as its one allowed divergence (gate B4) so it can never be “fixed” backwards.

Client: the gate in dismYield, the hammer refusal in dismSelToggle, the count and sentence in adamEveSplit and the Adam-and-Eve window, all in play/app.js. Worker: the hit predicate in /api/_internal/bulk_dismantle. Probes: tools/probe_dismmutant.py 9/9 (every client door, on a live save, red 1/9 against the build it replaces), tools/probe_dismmutant_ops.py 4/4 (the ops door, red 2/4 before), tools/probe_dismantle_parity.py 10/10 with the divergence pinned.

The dismantle result — a panel, and why it had to become one

A completed dismantle opens a centred list panel: one row per resource acquired, a socketables-returned line where sockets came back, and a close button. It is contained by construction — an inset:0 overlay centring a card whose width is capped in percent of its container, so no yield string can push it past the edge however many currencies it names. The rows are derived from the currency set, so a currency added later appears without touching the panel.

It replaced a single-line toast, and the toast was a real defect. The line was white-space:nowrap, and a full sweep names five currencies plus a refund count. Measured on a 430 px phone: that line drew 963 px wide and pushed documentElement.scrollWidth from 430 to 1178. A document wider than the viewport is answered by the browser zooming out — which is exactly what “the notification is resizing the game window” describes. Even the short breeding-egg line overflowed, at 582. The toast itself now sizes to its content with a percent cap and wraps, so it can no longer widen the document whatever text it is handed.

Overlays belong to the stage, not to the device. Six panels were position:fixed, which escapes the zoomed 1920×1080 stage and sizes them against the device viewport instead. An authored 1020 px card then becomes 94% of a phone while its children keep their authored pixel widths — which is why the devour window scrolled sideways: three flex:none cards at 330 + 66 + 330 plus gaps need roughly 770 px in a box near 400. The devour row now shares whatever width exists (flex:1 1 0 with min-width:0) and keeps its authored size wherever there is room, so a desktop is unchanged.

Client: dismDone and dismDoneRows in play/app.js; the results panel and the devour row in play/markup.html. Probe: tools/probe_popupfit.py (8/8, measured on a 430 px viewport).

The successful-craft popup names the grade and the tier

Build 0.47. The popup shown on a successful craft carried the item name only — no grade, no tier — on a screen whose whole purpose is telling the player what they just made. Two additions:

  • The name is painted in its grade colour, the same colour the bag tile and the item details window use.
  • A tier badge is appended, built from the same roman-numeral helper the bag tile uses (tierRoman / romanN). There is one numeral table in the build, so the popup and the tile cannot disagree — which is the point of reusing the helper rather than formatting a second time.

The forge/upgrade toast has no tier of its own, and now says so. A grade attempt operates on an item whose tier is unchanged by the attempt, so there is no tier for that toast to report. It states that explicitly instead of leaving the field undefined — an undefined field is the shape that eventually renders as undefined or as a blank plate, and it also invites a future session to “fill it in” with a number that means nothing.

The scroll description promised an ink reroll that was never built

Build 0.47. The scroll's effect string ended “Rerollable for 3×T Ink”. No ink reroll exists anywhere in the build, and three separate facts say so:

  • The server's roll door for kind === 'enchant' charges no ink and has no reroll branch. There is nothing to call.
  • The sibling description string on the same item already said “a scroll can only be replaced, never removed”, with no ink claim — so the item was carrying two descriptions that contradicted each other.
  • This page's own Scroll rerolling section states the real rule: there is no separate reroll action and no ink cost, and applying another scroll over a socketed one is the reroll.

The client sentence is removed. The rule itself is unchanged — only the false claim about how to invoke it is gone. This is the standing lesson from the class-switch confirmations: UI text is a claim about a code path, and a price quoted for an action that has no code path is a promise the game will refuse to keep.

There were TWO copies of the claim, and both are now gone. The second lived in the codex data file codex/items.csv, in the Effect column of the Scroll rows ITM-0381–ITM-0390 (all ten tiers), reading “…; rerollable for 3×T Ink”. Removed 2026-08-10 as a pure suffix strip: the clause contains no comma, quote or newline, so the field stayed unquoted and no other column moved — verified by re-parsing, 606 rows and 13 columns before and after, exactly 10 changed cells, all in Effect, CRLF line endings preserved. The Scroll Effect now reads “random Local enchantment roll — flat Attack/Defense/HP or item-local % Attack/Defense/HP”. Nothing parses that clause for a stat — scroll legality has been judged on the rolled result since the 2026-07-31 ruling — so this is a text-only change.
Adjacent and deliberately left alone: ITM-0395 (the Ink material) authors “scroll crafting + grading + rerolling”. That one is not the false price — ink genuinely buys the replacement scroll, and applying a replacement is the reroll — but the word invites the same misreading and is worth a ruling.
