Where the hatch is decided

The server draws the hatched grade and tells the client. POST /api/hatch carries the egg's id and its grade; the server reads that grade's row from egg_hatch_weights.csv, draws against those weights with a secret-keyed HMAC, records the result and answers it. The weights are never restated in code, and there is no fallback — an egg whose grade the file does not author hatches nothing rather than defaulting to the lowest tier, because a default would quietly become the balance.

An egg hatches once, forever. The result is stored against the egg's own id, not a key the caller chooses, so a retry or a lost connection replays the same creature. Re-submitting the same egg while claiming a richer grade cannot re-roll it.
