Implementation notes

  • Unlink (lane linkprov 2026-11-05, board N4 / docs/mobile-app-2026-11.md § 6 lane 2): POST /api/account/unlink {provider}, cookie or bearer. The PlayerDO drops the identity row and the Worker releases its world-ledger (A13) and legacy idx claims, so that login signs in fresh or links to another player. Refused: 401 no session, 400 bad_provider, 404 not_linked, 409 last_signin (the account keeps at least one sign-in), 409 is_account (a legacy Steam account IS its steamid; that row is never removable). The client reads /api/account/identities for the Linked Sign-ins row and masks each id to its last 4 characters itself; it sends a provider name only, never a uid. Probe tools/probe_linkprov.py.
  • Doors: GET /api/auth/providers (the gate's list), /api/auth/steam + /callback (web), /api/auth/steam/ticket (the Steam shell), /api/account/identities, /api/account/link, /api/account/merge, /api/account/reset, /api/account/delete and /delete/cancel, /api/logout, /api/me, /api/name/claim.
  • Sign-in handoff (lane authhandoff, security row SEC-13): /api/auth/<provider>?handoff=<target>, target exactly herumon://, capacitor://localhost, https://localhost or http://127.0.0.1:<port> (else 400 bad_handoff, no redirect); the callback 302s to <target>/auth?code= (60 s, single use) instead of setting the cookie; POST /api/auth/exchange {code} answers {token, expires}, the same 90-day session, sent as Authorization: Bearer and accepted wherever the cookie is (logout, session-end and bans end it the same way). /api/* answers CORS for those origins only. Client: play/index.html __HT_TOK / __HT_AUTHCODE; Steam shell: steam/bundle_server.js GET /auth. Probe tools/probe_authhandoff.py.
  • The client reads the provider list once at boot (window.__HT_AUTHP); the Link Account row's segments are that list.
  • Reset scope: src/worker.js T61 block — every realm-scoped table goes, the wallet_ledger keeps rows with prov LIKE 'paid_%', the identity rows stay. Probe tools/probe_t61_resetall.py.
  • Deletion: POST /api/account/delete with {confirm:'DELETE'}; the save is flushed first so a cancel inside the 7 days restores it whole.

Team notes (moved off the public page 2026-11-04)

The lines below stood on the public page until 2026-11-04 and are kept verbatim. The public page lists the live providers (Steam, Google, Discord; /api/auth/providers on 2026-11-04 answered apple:false) and drops the doors, ruling ids and the Networking pointer.

Your account is the login you sign in with. The server mints it the first time that login arrives, holds every save it ever accepts, and is the only side that decides what the account owns. The game never stores a password of yours and never sees one: every sign-in goes through the provider's own page.

  • One door per provider. The sign-in gate shows a button for every provider the server has configured: Steam always, and Google, Discord and Apple when their keys are set (0.93: Steam, Google and Discord are configured; Apple appears the day its key does). The list comes from the server (/api/auth/providers), so the gate never offers a door that does not open.
  • The Steam client signs you in by itself. Inside the Steam download the shell hands the server a Steam session ticket; there is no page to visit. The web build at playdfmc.com uses Steam's own sign-in page.
  • Signing in from an app. When the game runs from a page that is not playdfmc.com itself (the Steam download serving its own copy, the phone app), the sign-in opens in your system browser and comes back to the game with a one-time code, good for 60 seconds and once only; the game swaps it for your session. Only the game's own addresses can receive that code. Nothing changes on playdfmc.com.
  • Your identity is the provider's id (Steam ID, Google subject, Discord id). That id is the account; the name you pick for your character is a separate thing (below).

Only one window may write your save at a time. Opening the game in a second tab, window or device hands ownership to the newer one and the older one stops with “This window no longer owns your save”. Nothing is lost: the save the server holds is the last one it accepted. Close the extra window and reload the one you want to keep playing in (Networking has the mechanism, the ownership epoch).

Reset Progress (New Game)Resets everything (T61, D 2026-11-02: “per account reset should RESET everything”): creatures, gear, floor, badges, boards, ratings, bought bag slots, boons, pending trades — the climb starts again at Floor 1, Lv 1 with a new character. Two things stay: the login itself, and any Wraithgold you paid real money for (paid money is never deleted by a reset — T3). Free or earned Wraithgold goes with the rest.
Delete AccountTwo steps — what goes, then the typed word DELETE. The account is marked for deletion 7 days out and every device is signed out; signing in before the day offers to cancel. After it, the account and every linked login are gone. delete-account.html is the same flow from a browser.
