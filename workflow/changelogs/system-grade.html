GRADE MULTIPLIER — TEAM NOTES

The team record for the public page system-grade.html: its dated changelog (newest first) and the implementation notes that left the public page when the codex went player facing (D 2026-11-03). Lanes add each mechanic change here, never on the public page. Shape: python tools/codex_page.py --changelog system-grade.html in dfmc-client.

Changelog

2026-11-03 — codex review (dfmc-client lane codexreview-a; D 2026-11-03 “review the codex, clean it up, update whatever needs updating”). WIKI ONLY. The multiplier was listed on Attack, Defense, Utility and HP; the game applies it to Attack, Defense and HP only (play/app.js unit attack / defence folds and hpFor × qm; src/power.js the same) — Utility is an axis grade shown on the sheet, nothing multiplies it. The formula is now written against codex/grade_ladder.csv Quality_Mult, which the client loads at boot (qmDb) instead of a typed constant; the two endpoints bind via csv-bind. New section Grade on gear: a piece’s grade is the GF multiplier on its stat and the number of sockets it holds (same table, GF and the three socket columns), so the page covers both things the word “grade” means in the game.

2026-10-01 — the Divine twinkle is a baked sprite (dfmc-client 0.89 carry-over s4.6, PREP_PERFORMANCE § 3.3). LIVE on release since 2026-10-23 (0.89); the look is on the board for D. The Divine grade effect drew eight radial-gradient sparkles on the tile and on two pseudo-layers, and animated their background-size from 3% to 7% with a fade, which repainted every Divine tile every frame — a full bag multiplied it (28 tiles ran at 47.8 fps under 6× CPU throttle). The same eight dot positions per layer are baked into one sprite strip of 16 frames × 3 rows (tools/make_perf_tiles.py, drawn in code, deterministic) and the CSS steps through the frames and back, all three layers on one 5.2 s clock with whole-step phase offsets, so a tile repaints one small blit about three times a second instead of 24 gradients sixty times a second (60.1 fps on the same bag). What changes for the eye: the dots grow and brighten in 16 steps rather than continuously, and the three layers no longer beat against each other at 5.2/6.9/4.4 s. Gate tools/probe_perf_6.py.

2026-09-14 — the grade effect plays behind the soul slot’s creature icon (#894, D). LIVE on release since 2026-09-14 (0.80). The equipment row already played it in two places, on the gear item’s own icon and behind the soul readout; the soul’s creature icon sits between those two and never had it. It takes the SAME props off the SAME row, so there is no second opinion about which grades glow, and the art takes z-index 1 so the effect stays behind it. The gate’s oracle is the game’s own gfxHas() per row rather than a list of grades, so if the set that carries an effect ever changes, the expectation moves with it.

2026-09-05 — All-In plays out its attempts (board 3.7, D). LIVE on release since 2026-09-06 (0.70). The server still decides the whole burst in one keyed draw and books the spend before anything moves; what changed is the show. Each attempt now takes the alchemic circle in turn with a counter: the circle winds up with the bubbles, then the verdict — a fail stops it with a jolt, drops the item, etches cracks that deepen with the streak, puffs smoke and heats the circle’s rim from gold toward red; the deciding success flashes, sends a light column up behind the circle and sparks out in the new grade’s colour, lifts the item and re-tints the circle (Divine and up dim the window and turn slow rays first). Out of resources lands the same way in red. One click skips the attempt on stage, click-and-hold runs the rest fast, and closing early lands on the usual result line. Single attempts are unchanged.
