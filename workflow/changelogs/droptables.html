Who rolls the drop

The server rolls it and tells the client. The client renders the grant and never reports a drop of its own, so there is no second opinion to reconcile. Every number the roll uses is read from the files on this page — nothing about a drop is hardcoded in the backend, and there is no fallback constant anywhere in the path: if a table fails to load the drop simply does not happen and the account is flagged (drop_data). A default would quietly become the balance.

StepSource
Does it dropdrop_chances_by_floor.csv — one independent roll each for gear, enhancement and egg, per kill, at that kill's rarity. The kills are the ones the server derived from the seeded spawn slot, so floor, rarity and count are its own facts.
What gradedrop_grade_weights.csv for the floor's band. Enhancements use the band one behind gear, and that rule is read from drop_rates.csv (Enhancement_Grade_Rule) rather than assumed.
Which baseThe server picks it, uniformly among the gear bases at that tier — the rule this page already authors. Enhancements split evenly across gem / rune / scroll, then pick uniformly within. The client used to do this differently: it picked a category|family bucket uniformly and then picked inside it, giving a base that sits in a two-item family far more weight than one in a ten-item family. That was a deviation from this page rather than a balance decision, and moving the pick to the server corrects it — expect the visible distribution to change.
What tierThe zone boundaries authored in floors.csv. The client's ceil(floor/10) is a hardcoded restatement of today's zone layout — re-author the zones and it silently produces the wrong tier.
Only when earnedThe roll runs in the credited branch only. An uncredited battle — over the spawn budget, over a rate cap — earns nothing and therefore drops nothing.
Once onlyRecorded against the battle's event id, which is already deduped, so a retried or replayed battle returns the same grant instead of a second one.
How the pieces divide. The player’s Durable Object makes the draw, because that is where the secret-keyed generator lives; the Worker maps that draw onto items.csv and substitutes the concrete base on the way out. The split is not decoration: items.csv is around 208 KB and the chance tables travel inside the battle request body, so adding it there would put 208 KB on the hottest path in the game, every battle. The Worker holds it module-cached instead and the object never sees it. If it cannot be loaded the drop is dropped rather than invented, and the raw draw is stripped before the client sees the response.
Balancing. Change a rate here and the live game changes with it — the backend reads these files at DATA_PIN on release and at main on dev. No code edit, no deploy.

How Drops Work (paragraphs 2–3)

Per-kill chances are scaled on the game-wide rarity value ladder — C 1.0 / UC 1.5 / R 2.5 / SR 4.0 / SSR 7.0 (the same ladder as XP and Ichor) — and normalized per floor against codex/encounter_weights.csv, so each drop family lands exactly 10% per battle (3 kills) in expectation on every floor of the tower. Rarer kills pay better; the floor-wide economy never drifts.

All chances on this page are read live from the codex CSVs — drop_chances_by_floor.csv, drop_grade_weights.csv, key_drop_rates.csv, boss_loot.csv, first_win_drops.csv — the same tables the game reads. Nothing is hardcoded.

Boss Keys (paragraphs)

A single zone-specific Key (ITM-KEY-010…ITM-KEY-100) is required to enter a boss floor and is consumed on entry. Every wild creature defeated on the zone's 9 preceding floors rolls for that zone's Key, per creature, scaled on the rarity value ladder and normalized so a minimum-win journey through the zone yields exactly one Key in expectation.

Gates: a zone's Key cannot drop until the character has banked that zone's Min_Wins wins AND Min_Kills wild kills (zoneWins/zoneKills in the save, counted per zone, wild battles only — a boss win advances neither). Below either gate the roll is skipped entirely.

A Key that drops into a full inventory is DESTROYED. Every grant goes through one shared space check: no free item slot means the drop is discarded, never queued and never held — the victory screen reports only the generic "N drops lost — inventory full" and does not say a Key was among them. Since keys are the rarest item lane in the zone (0.46% per Common kill in Desert Plains, ~1 per 60 battles), a player farming with a full bag can lose several keys without ever knowing. Reported live 2026-08-01 by a player stranded on floor 29 with 235 zone wins and no key; his context snapshot read invCount 80 / invCap 80.

Void Apex rate (D, 2026-08-25): on each Apex key floor (101, 103, … 119) one Key is expected every two hours of chance at one won battle every 15 seconds — 1,440 kills per Key, split by the rarity ladder, normalised on that floor's encounter mix. Those ten rows are generated from that sentence (tools/gen_keyrates.py), never hand-typed; the tower's ten rows keep their authored minimum-win normalisation.

Boss Loot, egg paragraph

One native egg — a Stage-1 egg of any line that spawns on the zone’s floors (floor_creature_rarity.csv: a line counts when any of its stages spawns there; the egg is its Stage 1) — 69–87 lines per tower zone, not just the ten lines creatures.csv files under that zone as home, weighted by the canonical rarity chances 30/30/20/10/10 (C/UC/R/SR/SSR) normalized over the tiers present in the zone. Grade from the boss's floor band, clamped to the Legendary wild-egg cap — breeding remains the only path to Divine+ and Void creatures. Void Apex bosses (102–120): the pool is the Apex's own line list (all 100 lines) and the tier weights come from that boss floor's row in apex_boss_egg_rarity.csv instead of the 30/30/20/10/10 above; the egg is any line, including the lines of the three creatures in the fight — nothing is excluded (D ruling 2026-08-27: “apex boss is any egg ok”). Full mechanics on Void Apex. On DEV since 2026-08-27, on release at the next push.

Drop rules table, changed cells

Weapon and Gem sources carried “(crafting removed 2026-10-01)”; Weapon grade rule “Divine+ never drops — the Scrap grading gamble only”; Boss Key “One expected Key per minimum-win zone journey. Consumed on boss entry.”; Scrap “Feeds gear crafting.”; Ichor “(#772) · egg dismantles (breeding.csv Egg_Dismantle_Ichor) … Feeds the Ichor gamble — the only source of Divine+ gear.” (wrong at the pin: gear grading is paid in Scrap, grading.csv); Dust / Essence / Ink “(tier × grade#) … Feed enhancement crafting.”

The egg lane names a line, and the server is the one that names it. A wild egg is the Stage-1 egg of the line that was defeated, so the grant needs a species as well as a grade. Of the three kills in a battle, one is the spawn the server itself derived from the seeded slot — that creature’s identity is the server’s own fact and is used directly. The other two have no server-derived identity; the client names them, and the claim is accepted only if this floor’s own creature table authors that creature at the tier the kill was already clamped to. A claim the floor does not author is discarded and that kill grants no egg — the client can never talk a valuable line out of the server. The grade is band-rolled as above and then clamped to Wild_Egg_Grade_Cap in drop_rates.csv (Legendary), with the grade ladder read from the order of drop_grade_weights.csv rather than restated in code. This clamp is load-bearing: the 91–100 band authors an Abyssal weight, and without the cap a wild egg could hatch above the ceiling that makes breeding the only path to Divine and above. No cap authored means no egg is granted, the same no-fallback rule the rates use.

The balance table that was prose

boss_loot.csv authored the egg's line weighting as Egg_Line_Weighting,rarity_appearance with “30/30/20/10/10 (C/UC/R/SR/SSR)” inside the Notes cell. Notes are prose, not data: nothing could read them, and the client carried the numbers as a literal. They are five Params now — Egg_Line_Weight_C through _SSR, values unchanged. A formatting fix, not a balance change, and the same failure the enchantment magnitudes had.

A drop that throws now says so. An exception in the drop roll used to leave drops simply absent, which is indistinguishable from “nothing dropped”. The boss lanes vanished for an entire probe run and the only trace was a flag nobody reads; the response carries dropNote now, and it named the cause in one run. Same lesson as the swallowed floor sync — a refusal that looks like a null result is the worst kind.

Probes. tools/probe_bossloot.py 9/9 and tools/probe_bosskey.py 5/5, full stack. The loot probe climbs to a boss floor the honest way (the Genesis rule caps a new account at floor 2) and waits out the spawn budget between kills. The key probe deliberately has no end-to-end “a key dropped” test: the cheapest authored gate is 29 wins / 87 kills, every credited kill costs a spawn credit refilling at one per minute, and the chance behind it is 1.4% for a Common — roughly ninety minutes to open the gate and hours more to land one. It tests the gate, the clamp and the naming, which are the parts that can be attacked.

Void Apex note (as it stood)
