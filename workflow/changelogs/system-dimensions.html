SHIPPED IN 0.95. Shop: the five key rows (premium_shop.csv SHOP-006..010, now Enabled 1 in this batch) draw the key icon over its VFX loop (Key_Icon / Key_VFX_Sheet, stepped by transform like the trader's coin fire), a Theme_Primary border, "Held: N" from the server's key ledger and a USE button. USE opens a confirmation: key, dimension, the permanent buff and its text, five floors of five battles, the resource it pays, "the key is used up when you enter; you cannot go down; dying or leaving returns you to Floor N" (or the Infinite Abyss). ENTER calls /api/floor/dim/enter with the floor (and Abyss) the player stands on. Dimension view: "<Dimension> — Floor N", battles remaining on the floor, Floor N of 5, banked this run, the reward per win, the buff panel, ENGAGE (RESUME BATTLE when a fight is armed) and LEAVE DIMENSION. The plate is the dimension's Floor_Plate under the floor's Plate_Filter, in the view and behind the battle. A fight is built from the server's descriptors (level, quality, gear grade, the floor row's Tag_Tier / Tags, HP x HP_Mult x the buff's hpMul, AI tier); every creature carries the buff as the apex boss chip ({sig, perm}, the skull chip under its feet, hover for the text) and its sprite takes Creature_Filter. A win goes to /api/battle/dim/win (the wallet takes the server's balance; XP, class XP and party XP are the answer's) and shows a small banner: the themed resource and XP only, never a drop, egg, Ichor or streak line. A death ends the run (/loss; no tower defeat screen, no streak loss, no Abyss reset); fleeing a fight, the leave button and any floor travel ask first and end it (/leave). The end screen (cleared / fell / left) says the battles won and what was banked, and RETURN travels to the run's stored return point (and re-enters the Abyss run when it was entered from there). A reload resumes the run from GET /api/floor/dim. All text through the l10n layer (strings_*.csv m_dim_*, five languages). No portal or map entry.
At release: hub.html links system-dimensions.html again, and the player page says the dimensions are open (buy a key in the premium shop, USE it from its row, confirm, five floors of five battles that pay the key's resource, leaving or dying returns you to the floor you came from) — the K1 "At release" lines, applied at release, not now (the public page shows the live build).

2026-11-04 — K2 server + battle engine (D chat 2026-11-04; manager defaults D 2026-11-04 "decide yourself"; dfmc-client lane K2, spec docs/dimension-keys-2026-11.md). SHIPPED IN 0.95. The server sells, spends and runs the keys: /api/shop/buy grants a key row into a server ledger (dim_key_ledger, paid, never an item: no trade, dismantle or export) in the same step as the 20 Wraithgold debit; GET /api/floor/dim, POST /api/floor/dim/enter|fight|loss|leave and POST /api/battle/dim/win own the one live run per account (enter spends the key; five floors of five battles in order; each credited win pays the floor's Reward_<Resource> and party / soul / class XP at the ordinary per-kill rate, nothing else; death or leaving answers ret, the floor the player stood on, clamped to their progress; a replayed win answers the same and pays once; a win under Min_Battle_Ms is 429). Encounters are a pure function of a server seed (src/dimension.js). Engine (src/battle_round.js / src/battle.js, play/battle_module.js rebuilt): Enchanted Haste acts first (only a class ultimate before it); Inscribed Writ halves debuffs on it, doubles its buffs and doubles the debuffs it inflicts (knobs ride the chip; half-up, min 1 turn); a signature chip is never read as a debuff, so a cleanse can no longer strip Rust Fury / Sanguine Ward. Swollen floor 5 eased (manager default): dimension_floors.csv gains a Key_ID column; a row carrying one is a sparse per-dimension override (empty cell = the shared row). DK-ESSENCE floor 5 fights Common quality + Uncommon gear: a level-90 party wins 60% of those battles (was 40%; tools/sim_dim.mjs, 20 seeds), the other four dimensions unchanged. The page's floor-5 bindings now name the shared row (Floor=5&Key_ID=) - binding only, the text did not move. Shop rows SHOP-006–010 stay Enabled 0 until the client (K3) ships. Gates: tools/probe_dim_server.py (local worker, D's save), tools/probe_dim_engine.mjs. At release: system-dimensions.html says the dimensions are open (not "coming soon") and the floor-5 row notes the Swollen Dimension fights lighter gear (Common quality, Uncommon gear) — applied with K3.

Implementation notes

  • Where the build spec lives: dfmc-client docs/dimension-keys-2026-11.md § Build spec (state machine, doors, battle generation, manager defaults, lane cut).
  • One price, one place: the key price is premium_shop.csv Cost; dimension_keys.csv names the SKU only.
  • Rewards are baked, not computed live: a change to the drop tables, the dismantle table or battle Ichor moves acquisitionPerBattle; re-bake Reward_* and run --rewards.
