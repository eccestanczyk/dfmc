THE STAGE

Other Systems › The Stage

Every screen in the game is drawn inside one fixed 1920×1080 box that is then scaled to the device. Nothing in the client is authored in device pixels. Getting this wrong has produced three separate defects in a single day, so it is written down here rather than rediscovered a fourth time.

fitScale

The stage carries zoom: fitScale, where fitScale = min(innerWidth/1920, innerHeight/1080), recomputed on resize.

DevicefitScaleStage drawn at
Desktop 1600×9000.8331600×900 — fills exactly
Phone 690×6740.359690×388, letterboxed top and bottom

THE RULE: an authored px is a STAGE px. What the player sees is authored × fitScale. A 14px label is about 5 CSS px on a phone. Never judge a size by reading the source — measure the drawn result at a phone viewport.

The stage corner is not the screen corner

Because the stage is letterboxed on a phone, its top-left sits at roughly y = 143 on a 674px-tall viewport, not at 0. HUD elements are positioned against the stage, which is the corner a player reads as the game's edge. A probe that clicks “the top-left of the screen” is clicking page background, not the game.

position:fixed escapes the zoom

A position:fixed overlay is not scaled by the stage's zoom, so any percentage sizing on it resolves against the real viewport while everything inside it is still in stage units. This asymmetry is the cause of the defects below.

The menu HUD

  • The button sits flush in the stage's top-left corner — left:0; top:0 on its host — and is rectangular, border-radius:0. It measures 143×56 stage px. It was previously inset 24,8 with border-radius:999px, a pill. (D, 2026-08-05.)
  • Its dropdown is 1780px wide plus 18px padding = 1816px, so it fits the 1920px stage with the host at left:0. Moving the host any further right narrows that margin.

Rule of thumb from these: anything under about 22 stage px is illegible on a phone. The item tile is 135×135 stage px, so a 30px badge is roughly 22% of it — large enough to read without swamping the art.

Measuring it

elementFromPoint and getBoundingClientRect disagree under CSS zoom, so an occlusion test built on the two together reports elements that are plainly on screen as invisible. elementFromPoint also answers null outside the viewport, and returns the element beneath anything marked pointer-events:none. Prefer geometry plus computed style, and convert offsets back into stage units by dividing by fitScale before comparing them to authored values.

Probes: tools/probe_menucorner.py, tools/probe_devourfit.py, tools/probe_shoplist.py — each measures at a phone viewport, not only at desktop.
