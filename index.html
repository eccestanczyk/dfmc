Concept

A creature-collecting competitive turn-based RPG where players climb an ever-ascending tower floor by floor. Each floor is a simple map where the Collector triggers battles until a win threshold opens the portal to the next floor. All metagame systems (breeding, crafting, hatchery) are accessible as UI panels at any time during PvE — no physical base.

Game modes

Ladders

  • PvP ladder — ranked 3v3 combat, tracked per season and all-time
  • Progress (floor) ladder — highest floor reached, tracked per season and all-time

Art pipeline

Dark-fantasy painterly style generated with gpt-image-2-2026-04-21 via OpenAI API (sizes 1024×1024 / 1536×1024 / 1024×1536 only). Generation model is gpt-image-2-2026-04-21 everywhere (creatures, floors, props, item icons) — it is sharper than every predecessor (~1.5–2× the edge sharpness of gpt-image-1.5, ~6× gpt-image-1); the legacy gpt-image-1/gpt-image-1.5 models are deprecated for generation. Transparency caveat: gpt-image-2-2026-04-21 does NOT support background:"transparent" (the API rejects it). Generate opaque on a flat neutral background whose value CONTRASTS the creature's dominant luminance, then obtain transparency via the remove.bg + despill pass below. Adaptive background rule (remove.bg segments by contrast — a same-tone background destroys the subject): dark/black-dominant creatures → flat WHITE or light-gray background. To force gpt-image-2 to actually render a light backdrop, describe the BACKGROUND as "a plain flat pure-white seamless backdrop" — but do NOT describe the LIGHTING as "studio / high-key / bright even lighting / product shot": that phrasing desaturates and flattens the creature (measured creature saturation drops to ~16–38 vs ~70 on a dark backdrop), producing washed-out photographic results that lose the dark-fantasy style. Background color and creature lighting are INDEPENDENT. Always keep the creature description on "richly saturated vivid colors, dramatic dark-fantasy rim lighting with deep shadows, moody painterly rendering, NOT washed out, NOT overexposed" regardless of background value; light/white-dominant creatures → flat dark-gray or black background; mid-tone creatures → mid-gray (#808080). NEVER strong chroma (green/magenta/pink) — they bake edge halos no pass can fully clean. After a white/light background, run a white-halo despill (darken over-bright edge-band pixels) in addition to the green/magenta despill. Native-transparent generation is only available on the deprecated 1.x models and must not be used. All creature art follows this pipeline:

Creature art pipeline (per line, 3 images)
  1. Stage 2 (core concept) — Fresh text-to-image generation via /images/generations on gpt-image-2-2026-04-21. Full descriptive prompt with stacked anatomical deviations (4–5 per creature), explicit color palette, combat-ready stance, generous framing margin, transparent or neutral-gray background. Prefer background: "transparent"; fall back to background: "opaque" with solid gray (#808080) or black (#000000) in the prompt if transparency causes edge issues. Never green or magenta/pink. Upload raw to codex.
  2. Stage 1 (infant) & Stage 3 (final form) — Stage 2 image sent as visual reference via /images/edits on gpt-image-2-2026-04-21. The prompt is a full descriptive brief for a new creature — never framed as "edit this image" or "make a smaller/bigger version" (that drifts/fuses anatomy). The image reference maintains visual lineage; the prompt drives a fresh generation. Same background approach as Stage 2 (transparent or gray/black — never green or magenta). Known limitation: the /images/edits endpoint ignores flat-background and center-70% framing instructions when handed a reference — it paints dark atmospheric scenery and fills the frame regardless of prompt emphasis. This is cosmetic only: the subject renders correctly and the matte pass strips the dark haze cleanly (~2–3% semi-alpha, no halo). If a truly clean solid background is required, use /images/generations (text-to-image, no reference), which respects background and framing — at the cost of the Stage-2 visual-lineage link.
  3. Art-approval gate (do NOT crop early) — "Generate new option", "Generate new crop"(when art not yet approved), and "Regenerate" place the RAW generated art WITH its background into the slot and stop there. remove.bg cropping is a PAID step and runs ONLY after the art is approved. Never remove.bg a freshly-generated option/regen — it wastes credits and skips the approval gate. Cropping happens at approval time (approve option → crop → promote to A).
  4. Background removal — Separate pass after art approval. Matte-only methods only — the method must never repaint the subject. Priority order: (1) remove.bg API — zero RGB drift, clean edges, commercially licensed only when processed with paid credits (subscription/PAYG); the 50 free calls/month return 500×500 previews that are not commercially licensed — quality-gate use only, never shipped. (2) BiRefNet general checkpoint (MIT) locally on the dev PC — zero drift, best on fine detail, free; use plain BiRefNet, never BRIA RMBG-2.0 (BiRefNet-based but non-commercial license — disqualified for a commercial Steam release). (3) rembg new_session("isnet-general-use"), plain, NO alpha matting — light fallback for simple silhouettes. Never gpt-image-1/gpt-image-2-2026-04-21 edits for removal (regenerates the whole frame — measured 12–17 RGB drift, warps anatomy) and never rembg default u2net (halos, destroys ethereal creatures). Despill pass (mandatory on legacy chroma art): creatures generated on the retired green/magenta backgrounds have colored fringe baked into their edge pixels — no matte can remove it since it is part of the subject. After matting, neutralize the cast in the partial-alpha edge band only (interior untouched): subtract magenta cast max(0, min(R,B)−G) or green cast max(0, G−max(R,B)), weighted by edge alpha. Fixes ~99% of legacy images in place without regeneration; only creatures whose soft ethereal edges (wisps, fine foliage) carried their color in the chroma bleed are regen candidates. New art on transparent/gray/black needs no despill. Originals preserved in codex/images/originals/ before overwrite (>1MB files: read via the git blobs API, not the Contents API inline field). BG_Status: has_chroma → bg_pending → bg_approved or manual.
  5. Crop option slots — the codex shows each creature's candidate cutouts as sequential tabs: A = codex/images/<ID>.png (main/original), B = codex/images/cropped/<ID>.png, C = codex/images/cropped_c/<ID>.png, D = cropped_d/, etc. A new option ALWAYS fills the next empty slot in order (A→B→C→D). Never skip a slot — the codex will not render a C when B is empty. If only A exists, a new crop goes to B; if A+B exist, it goes to C. On approval, the chosen crop is promoted to A (main) and all other slot files are deleted so no dead tabs remain. Slots are contiguous and RESHUFFLE on deletion: deleting any slot shifts every higher slot down to fill the gap — delete A → B becomes A, C becomes B, D becomes C; delete B → C becomes B, D becomes C. There is never a gap (no C without B, no A absent while B exists). Physically this means moving each higher slot's file content down one path (cropped/→main, cropped_c/→cropped/, …) and deleting the now-empty trailing path.
  6. CSV update — Image_Path and Art_Status set immediately after each generation. Statuses: pending (awaiting approval), approved (art locked, do not regenerate), redo (flagged for regeneration).
Floor art pipeline (per floor, 3+ assets)
  1. Battle background — Text-to-image, 1536×1024 (regular floors) or 1024×1024 (boss arenas). Prompt includes zone visual theme, encounter type, and atmosphere. Transparent background not used — these are full scene paintings. Tracked in codex/floor_assets.csv.
  2. Parallax layer — One per zone (10 total), 2304×1024, seamless horizontal tile. Atmospheric depth layer behind the battle background for ultrawide displays.
  3. Props — 3–4 per zone, transparent background. Environmental dressing placed on the floor map: standing stones, skull heaps, glowing crystals, etc. Tracked in codex/prop_assets.csv.
  4. Map preview — Two renders per floor: empty (background + props, no creatures) and populated (with creatures placed). For approval only, not shipped assets. Tracked in floor_assets.csv Map_Preview_Status / Map_Populated_Status.

Floor assets live in floors/backgrounds/, floors/parallax/, floors/props/{zone}/. Preview/mockup floor art now lives under _parking/floors/. The floor sheet (codex/floor_assets.csv) references which assets each floor uses — decoupling floor identity from art allows infinite floor extension later by reusing zone asset pools.

Item art pipeline (per base type, 1 image)
  1. Generation — Text-to-image, 1024×1024, opaque flat mid-gray #808080 background, then remove.bg + despill (gpt-image-2 rejects transparent). Every weapon (36), armour piece (40), and accessory tier gets its own icon; enhancement tiers (Rough → Sublime, Faded → Elder, Tattered → Fated) get tier-specific prompts describing the item's visual state at that power level.
  2. Approval — Same status flow as creatures: prompt_ready → generated → approved. Tracked in codex/items.csv Art_Status column.

All 585 items catalogued in codex/items.csv with flavor text and image prompts. Prompt boilerplate: isolated dark-fantasy game item icon, oil-painted style, dramatic rim lighting, rich vivid colors, item centered 70% of frame, three-quarter angle, on a plain flat mid-gray (#808080) seamless background.

Character system

One character per realm, always

Every account has a character in every realm they have unlocked, starting at level 1. The character slot is permanent — death does not remove or demote the character. Only their items, creatures, and class XP are lost.

Player level, character level, class level

The player level is account-wide and uncapped: it accumulates every point of XP the account ever earns, uses the standard curve to 100, then costs a flat 639,723 XP per level forever (~640 battles, ~21h). Creature, class, and character levels all cap at 100.

The character has a character level — a global level aggregated from XP across all classes. Character level scales base stats (HP, stamina, resistances). Each class has its own class level tracked separately, unlocking class-specific bonuses. Switching classes does not reset others. Switching the active class unequips everything attached to the character — all 8 gear slots return to inventory (socketed gems, runes, enchantments and attached souls stay on their items); the new class starts bare and is re-equipped from inventory.

Classes

Six classes, each a linear advancement line of three stages. The class advances at class level 33 (Stage 1 → 2) and class level 66 (Stage 2 → 3) — fixed breakpoints, not the per-line levels creatures use (D ruling, 2026-07-27). Advancing re-skins the character and moves it onto that stage's row in codex/classes.csv, so its Attack / Defense / Speed grades rise with the form; the stage is derived from the class level, so the two can never drift apart. There is no branching specialization; a Warrior is always a Warrior, just stronger and re-skinned. Characters use three stat axes only: Attack, Defense, Speed (Utility is a creature-only measure — a character can wield any ability regardless of stats). Speed is capped at 10 like all axes and has no gear sources.

Stat sums scale by stage, matching creature grade tiers spread across three axes: Stage 1 ≈ 12 (Common-tier), Stage 2 ≈ 16 (Rare-tier), Stage 3 ≈ 20 (SSR-tier). Every axis value stays ≤ 10.

Character creation opens on the class-select screen: Warrior, Archer, or Mage. Each option displays its two fixed starter creatures — one SR and one SSR line, at Worn quality grade: Warrior Ferrodrake (SR) + Ridgedrake (SSR) · Mage Phylactery (SR) + Pyriel (SSR) · Archer Typhon (SR) + Stormfather (SSR) — recorded in codex/classes.csv (Starter_SR / Starter_SSR, Stage-1 creature IDs). After picking a class the player names the character; creation then completes with that class, its two starter creatures (genders rolled 50/50 at grant, account-bound — never tradeable), and its T1 class weapons (main + off hand) equipped. The two unpicked starter classes become purchasable for 100 Scrap each — class + T1 weapons only, no creatures.

XP distribution & level penalty

End-of-battle XP is awarded to every creature in the party and the avatar, not only the participants. Dying in battle does not forfeit XP — a fainted creature or downed avatar still receives its full share. Each recipient's XP is then scaled by a penalty based on its own level versus the defeated enemy's level (diff = enemyLevel − recipientLevel). The two directions are asymmetric:

DirectionGrace (0% penalty)RampFloor
Enemy higher (under-leveled) — forgivingdiff ≤ +10linear +10 → +5090% at +50
Enemy lower (over-leveled) — strictdiff ≥ −3linear −3 → −2590% at −25

Under-leveling into hard content stays rewarding (push up freely); grinding trivial enemies is quickly gutted — the over-leveled curve reaches the 90% floor in half the level span of the under-leveled one. Full curve, chart, and live calculator: Other Systems › Level Penalty.

Core loop

Single active character

The game runs one realm character at a time. Switching realms switches the active character; only the active character simulates. There is no offline progression; being in-game is the only way to advance. All economy balancing is denominated in battles for this one active character (~30 battles/hour on autoplay).

Manual mode
Default state. Player directly controls the active character. Autoplay must be explicitly enabled to hand off control.
Autoplay mode
Opt-in. The active character grinds the current floor automatically. Disable to return to manual control.
  • Autoplay is off by default — the player opts in
  • Switching realms pauses the previous character entirely
  • Closing the game window pauses the character
  • No offline rewards — open game only

The earlier multi-tab simultaneous-simulation design (up to 4 realm tabs at once) is retired — one character farms at a time.

Floor presentation (Simplified Static)

There is no player avatar. Each floor is a static painted map (1536×1024 px, 3:2; parallax background at 1.5× for ultrawide; boss floors are 1024×1024 arenas). Creatures wander the map autonomously; hovering a creature highlights it by rarity; clicking (tagging) it starts the battle. Grid movement is archived — see Roadmap.

Map design

Maps are small and simple — no elaborate handcrafted circuits or secret areas. Battles start the same way on every floor: click a wandering creature. Floor themes are purely visual — they change the art, not the mechanics.

🌿 Outdoors
Visual theme only — open-air backdrop, grass and foliage dressing.
🕳️ Cave
Visual theme only — enclosed rock backdrop, darker palette.
🎣 Fishing
Visual theme only — waterside backdrop, aquatic dressing.

Floor theme is fixed per floor and purely cosmetic. The battle trigger (click a creature), win condition (consecutive win streak scaled by floor depth), and boss key drop are identical across all three themes.

🏆 Win condition
Win a streak of consecutive battles on a floor to open the portal. Threshold scales with floor depth: ceil(floor0.65) — floor 1 needs 1 win, floor 10 needs ~4, floor 50 needs ~13, floor 100 needs ~20. Losing a battle resets the streak to zero. Boss floors always require exactly 1 battle (the boss fight).
👑 Boss floors
Every 10th floor is a boss room (floors 10, 20, … 100). Entry requires consuming a Key, which has a chance to drop from any battle across the previous 9 floors. Guaranteed key: the first time a player completes floor 9 of any zone (floors 9, 19, 29, … 99), they are guaranteed a key drop for that zone's boss. This is a one-time reward per zone per character — subsequent visits use the normal random drop rate.

Wild spawns — persistent floor pool

Each floor holds a persistent pool of up to 10 wild creatures, refilled by a serial respawner: one spawn per 60 seconds while below cap. The timer runs in real time whether the player is on the floor, elsewhere in the tower, or offline; every floor ticks independently in parallel. A floor spawns its full pool of 10 the first time the player enters it; from then on the pool is persistent.

Sustained single-floor farming is throttled at the spawner; speed builds, like everyone else, scale through floor rotation (≈10 per floor per pass).

Wild quality & virtual gear

Every wild spawn rolls a quality grade once, at spawn, from the zone-banded weights in codex/wild_quality_weights.csv — floors 1–9 are all-Worn (×0.84), the curve begins at floor 11, and the roll is capped at Legendary — Abyssal–Void quality exists only through breeding and never appears in the wild. The rolled grade sets the creature's quality multiplier (QM) on Attack, Defense, and HP. There is no catching — wild creatures are fought, never taken; their lines enter the roster only through egg drops and hatching.

Deep-zone wilds also carry virtual gear: zone 1 none; zones 2–4 one tag; zones 5–10 both combat tags. The single tag is Fang when the species' Grade_Attack ≥ Grade_Defense, otherwise Carapace — never Heart (HP scales through QM only; wall inflation stays capped at the source). Tag value is the canonical tag implicit at the at-floor tier — no gems, runes, or item instances; nothing enters the loot tables. Drops, eggs, XP, and Ichor are computed exactly as before — enemy quality never feeds the reward economy.

Streak counter

After every battle, a compact rectangle appears mid-screen showing the current streak status as X / Y (battles won / threshold). On a win, X scrolls up to the new count and the text pops in size briefly. On a loss, the rectangle visually cracks and X rolls back down through each number to 0. The counter only appears on floors not yet cleared.

Boss key

A single Key is required to enter a boss floor, accessible via the portal or directly through the map selector. Keys are zone-specific items (ITM-KEY-010…ITM-KEY-100). Every wild creature defeated on the 9 floors preceding a boss rolls for that zone's Key. The roll is per creature and scales with the creature's rarity — on the game-wide rarity value ladder (C 1.0 / UC 1.5 / R 2.5 / SR 4.0 / SSR 7.0 — same as Ichor and XP), normalized against the zone's encounter weights so a minimum-win journey (3 kills per win) yields exactly one Key in expectation: p(zone, r) = mr ⁄ Σfloors(3 × ceil(floor0.65) × M̄(floor)). Void Apex zones (101–120) are the exception (D ruling 2026-08-25, report #533): each Apex key floor expects one Key every two hours of chance at one won battle every 15 seconds — 480 wins × 3 kills = 1,440 kills per Key, mix-weighted on that floor's encounter weights, the same ladder — derived by tools/gen_keyrates.py in the client repo (--check proves the file matches; the tower rows it never touches). Full table in codex/key_drop_rates.csv. Guaranteed key: the first time a player completes the 9th floor of a zone (floors 9, 19, 29, … 99), a key is guaranteed to drop. This is a one-time reward per zone per character. The Key is consumed on boss entry.

Boss loot

Every boss kill guarantees two drops, delivered on the conclusion screen (params in codex/boss_loot.csv):

  • One piece of equipment — a uniform pick among the Weapon / Armour / Accessory bases at at-floor tier; grade rolled one floor band ahead of the boss's band (the mirror of enhancements' one-band-behind; the final band clamps to itself).
  • One native egg — a Stage-1 egg of a line native to the zone (Home_Zone), weighted by the canonical rarity chances (30/30/20/10/10 over the tiers present); grade from the boss's floor band, clamped to the Legendary wild-egg cap. Breeding remains the only path to Divine+ and Void.

Defeat

Losing a battle does not remove the player from the floor. The team remains on the current floor and the win streak resets to zero. There is no forced exit, no floor lock, and no return to floor select.

Autoplay is disabled by default and must be enabled per character. A quick toggle sits directly on the gameplay screen; the Auto tab in the options menu holds the full customization. Healing

Healing items have been removed from the game entirely — there are no consumable heals, in or out of battle. The team is restored to full HP after every battle, win or lose. Attrition therefore exists only within a single battle; difficulty pressure comes from the streak reset on defeat, not from resource depletion between fights.

Every battle is a deterministic replay — initial state + per-round RNG seed + committed move log, persisted once per round before resolution renders. PvE has no move timer. Details: PvP, Timers & Persistence.

Turn structure

Simultaneous selection, sequential resolution. Both sides select actions blind (double-blind). Once locked, all actions resolve in Speed order — highest Speed acts first. Status effects queued (poison, stun, burn, etc.) resolve after move resolution. This makes Speed the decisive tactical axis: a faster creature can KO a threat before it acts, even if both sides chose to attack the same target.

Class ultimates

Every class line carries one ultimate, authored in codex/ultimates.csv (one row per line per stage, 18 rows). It is learned at class level 10 (authored per row as Learn_Level, so it can be retuned per line or per stage without a code change) — below that level the ultimate does not exist for play at all: no plate, no autoplay pick, no priority action, though the class preview still describes it. It costs the avatar's action for that round, is usable once per battle, and resolves in a priority bracket ahead of every normal action, regardless of Speed. Two ultimates cast in the same round tie on the committed round seed — a 50/50 both sides commit to blind. Spending is stamped on the avatar unit itself, so it survives a crash-resume and a PvP reconnect, and clears only when a fresh battle builds its units. An action denied that round (bind) does not consume it.

Resolution rules and edge cases.

  • Taunt redirects every enemy single-target hostile move that round — damaging and status-only alike — onto the taunter. Redirect is applied at resolution, so blind-selected actions land on him. Area moves are the only bypass, damage and debuff alike; a hybrid move's hostile half redirects while its self-buff half is untouched. Redirected status-only moves apply their debuff but are not hits, so they trigger no Paladin heal. The Knight rider (+10% Defense) lasts the rest of the battle; the taunt itself expires at end of round.
  • Paladin heal counts damaging impacts only: 5% of maximum HP per hit, every multihit component counted, damage-over-time ticks excluded, and never on a hit that downs him.
  • Vanish makes the Assassin untargetable by single-target moves (damaging and hostile status) for 1 / 2 / 3 rounds. A pending action against her retargets at random among the foes that can still be seen; if none can, the action is lost. Area moves still connect — that is the counterplay — and vanish does not cleanse: effects already on her keep ticking for the whole duration. She acts normally throughout. A taunter outranks vanish when both are up on the same side.
  • Retaliation answers each damaging hit taken that round with an instant counter on the attacker, per multihit component, and stacks Attack per hit up to its cap for the rest of the battle. Counters resolve outside the hit pipeline, so a counter can never trigger another counter.
  • Echo fires every slotted support ability (Power 0, self/ally scope) at once across the whole party. Percentage magnitudes scale by the stage fraction exactly; durations become ceil(d/2); integer components (Speed stages, shield hits) scale then round half up with a floor of 0, so a +1 stage echoes as 0 at S1 and 1 at S2/S3 while ±2 stages echo as 1 at every stage. A clause left with no live magnitude is dropped entirely. Echoed statuses carry their source ability's key, so the standing merge rule stops a half-strength echo overwriting a running full-strength cast. With no support ability slotted the ultimate is unavailable and cannot be spent.
  • Nukes resolve through the ordinary damage path — same formula, same 0.9–1.1 roll, same defences and statuses as any other move. The Mage figure is authored per target.

Autoplay carries a matching option, ULTIMATE — FIRST TURN / NEVER USE (default FIRST TURN): it fires on the first round the ultimate is legal and falls through to a normal move on any round it is not, retrying the next round. The PvP timeout/disconnect AI never fires it. In the client the ultimate is a stylised plate above the move parchment; once spent the plate goes dead and reads ( ULTIMATE USED ).

Character abilities — soul-granted moves

The player character has no innate abilities beyond a single fallback. Each ability slot mirrors the move of a creature soul equipped on the character's weapons and accessories. Rules:

  • Each equipped creature soul grants its corresponding move slot to the character (soul in slot 1 grants that creature's move 1, etc.)
  • Cannot equip 2 souls of the same creature
  • A creature whose soul is equipped cannot be summoned to the battle party
  • Character move damage uses the character's Attack; no STAB (STAB is creature-only)
  • Strike fallback: while no soul moves are equipped, the class has exactly one ability — Strike, Power 50, single-target damage, no cooldown (M-CLASS-STRIKE in codex/moves.csv). Equipping any soul move removes it. Creatures never have Strike — their fillers are their own CD0 kit moves

Battle party rules

  • In battle: 2 creatures + the character
  • Wild battles are 3v3: slot 1 on the wild side is the tagged creature from the map; the other two are extra creatures rolled by the floor's rarity chances, conjured for the battle only — they never consume the floor's pool or its respawn timer
  • Only 1 of each creature species per party
  • PvP tournaments: +3 creatures on the bench for sideboarding between matches in a Bo3

The base formula follows the proven creature-battler core. The increased/more split is bolted onto the modifier chain — increased sources add together (diminishing returns within a category), more sources multiply (always valuable). This rewards diversifying modifier sources over stacking one type.

Move system

Creatures have a fixed set of moves tied to their species and theme. Moves are not swappable or customizable. Metagame systems

All metagame systems are accessible as UI panels at any time during PvE floors, including during battles. They are locked during PvP. There is no physical base — everything is menu-driven.

Creature acquisition

There is no capture mechanic. All creatures come from eggs — either dropped in combat or produced via breeding. Every egg must be incubated in the Hatchery panel before hatching. Egg grade weights the hatchling's grade roll — it does not fix it. Any egg can hatch a creature up to 4 grades above its own grade, or any grade below it; higher-grade eggs shift the roll upward and away from the low grades, but the top grades stay rare from any egg. Full weight table in the Eggs codex.

🥚 Wild eggs
Drop from combat encounters — every defeated wild creature rolls its line's Stage-1 egg at a rarity-scaled chance (codex/drop_rates.csv, Egg_Drop_Chance_*; 10% per battle in expectation), grade from the floor band's weights. Grade range: Worn through Legendary only — no wild eggs above grade 6. Grade determines stat range at hatch.
🧬 Bred eggs
Produced via the Breeding UI panel by selecting two parent creatures and spending Ichor. No grade cap — can produce up to Void. Higher grade parents significantly increase odds of higher grade output. Hatchery level also increases the chance of higher grade eggs independently of parent grade.
⭐ Starter creatures
Granted at character creation via the class-select screen — each starter class carries two fixed creatures, one SR and one SSR line, at Worn quality grade. Genders roll 50/50 at grant; starter creatures are account-bound (never tradeable). Later class unlocks grant no creatures. Assignments: Warrior — Ferrodrake (SR) + Ridgedrake (SSR); Mage — Phylactery (SR) + Pyriel (SSR); Archer — Typhon (SR) + Stormfather (SSR).

Speed never appears on any soul passive. A creature whose soul is equipped in any slot cannot be summoned; one soul per creature across all 8 slots. A socketed creature is still a creature: it earns the same battle XP the party earns, it levels in the socket, and when it crosses its line's Evolve_Level it advances there, playing the same advancement scene a party creature does — which steps its passive and its granted move up a stage band. Soul grade, quality grade and XP all survive the change.

Soul grading — the final resource sink

Every creature's soul has its own soul grade on the shared Worn–Void ladder, independent of the creature's quality grade. All souls start at Worn. Soul grade is a permanent property of the creature — it is retained through advancement (Stage 1 → 2 → 3) and persists whether the soul is equipped or not. Grading a soul multiplies its output: the passive magnitude on armour slots, or the granted move's power on ability slots.

Modifier slots

💎 Gems — flat stats
Fixed flat modifiers. 3 gem types: Garnet (+Attack), Onyx (+Defense), Bloodstone (+HP) — 4.5 × T × GF each. Set at socket time, removal destroys the gem. On character gear: Local scope. On Tags: Personal scope. Up to 3 slots at Void grade.

Success gates are geometric distributions: the spread between a lucky (p10) and unlucky (p90) player on a single gate is ~22×. Failure costs currency only — no destruction, no downgrade. Raw chance: Void 0.5%.

Crossing between them

The two bags are separate menu destinations that share one window. The window carries a crossing button on the right of the category row, immediately left of Dismantling: in the inventory it reads SOUL BAG, in the soul bag it reads INVENTORY, and pressing it swaps the bag in place without closing the window. Nothing moves between the bags — an item lives in whichever bag its category belongs to and there is no transfer.

Crossing discards everything scoped to the bag being left: any open item detail panel, the slot shop, and every salvage mark plus the salvage mode itself. Marks belong to the bag they were made in, so a selection made in the inventory can never be carried into a soul-bag dismantle. Category, grade and type filters are stored per bag and survive the crossing intact.

Interim pricing. Every block in either bag currently costs 1 Wraithgold and every account is credited 100 Wraithgold, so slots are effectively free while the systems are being tested. The authored curves — the inventory's Scrap ladder and the soul bag's 50 → 2,800 Wraithgold ladder — are preserved in the same CSVs under Design_Currency / Design_Cost and are what real pricing returns to.

Bulk salvage

Both bags offer the same three modes: dismantle selected, dismantle all filtered, and dismantle by grade. A sweep never reaches outside the bag on screen — marks made in one bag are dropped on switching, and "by grade" resolves against the open bag only. The inventory sweep never takes boss keys or tags. The soul-bag sweep takes creatures and eggs; a class soul cannot be swept in any mode, and anything equipped, penned or socketed is not in the pool to begin with.

At full pricing, soul-bag expansion runs 19 purchases on a rising curve — 50 Wraithgold for the first block of 30, 2,800 for the last, 13,700 for all 600. A class soul occupies a slot for as long as the account owns it; a creature socketed into gear or placed in a breeding pen does not, because it has left the bag. The soul bag is its own main-menu entry, not a tab inside the inventory. Its filters are kind, grade and creature type; creature and class-soul icons both carry their current level; and the default order is class souls, then creatures, then eggs, sorted by grade and then level within each category.

Class souls

A class is held as a class soul — an item in the soul bag, one per class the account owns. Open it to equip it, which switches the active class and strips the character bare; all eight gear slots return to the inventory, and the switch is refused outright if the inventory has no room for them. A class soul is untradeable and undismantleable: it is bound to the account, and no salvage, bulk sweep or trade can consume one.

Class souls grade on the same Worn–Void soul ladder as creature souls (codex/soul_grading.csv) — the full five-currency bundle per attempt, the shared 100 / 90 / 70 / 50 / 35 / 20 / 8 / 3 / 0.5% success chain, and a failure that consumes the bundle and changes nothing else. Grade is stored per class line and survives class switching, since the soul is a property of the class and not of the character wearing it.

A creature can be dismantled from its details window, which also shows its types as badges in the header. It salvages for the same Ichor an egg of that grade salvages for. Bulk salvage never touches creatures — that is a deliberate, one-at-a-time act.

Creature grading design principle

Each creature line has one fixed set of 4 identity grades — Attack / Defense / Utility / Speed, scale 1–10 — that stays constant across every advancement stage in that line. Advancement scales actual battle stats later; it does not change the identity shape.

Creature naming

Every creature line name is a single word — no multi-word names, no "The ___". Dark-fantasy tone, frequently a modified myth or religious reference. Line_ID in the CSV is the uppercase line name. The three advancement stages now carry distinct names: Stage 3 keeps the line name, while Stages 1 and 2 are real-word precursor names drawn from the final name's own myth, etymology, or life-cycle (e.g. Veliger → Hafgufa → Kraken; Eyas → Haggard → Roc). Applied across all 100 lines in codex/creatures.csv. Line_ID stays the final name, so advancement links and encounter IDs are unaffected.

Image generation conventions

  • Background & removal rules: see the canonical Art pipeline section (Overview) — the single source of truth. In short: generate on transparent or gray/black, never green or magenta (baked-in edge fringe); remove matte-only (remove.bg paid / BiRefNet local), then run the despill pass on any legacy chroma art.
  • 3-stage workflow: see canonical Art pipeline section. In short: Stage 2 first (text-to-image), Stages 1 & 3 as fresh generations using Stage 2 as visual reference — never an "edit" instruction.
  • Every prompt stacks 4–5 anatomical deviations so the creature reads as its own species, not "real animal + one gimmick."
  • Every prompt names an explicit color palette. No two lines in the same zone share a palette.
  • Creatures must be in a natural combat-ready stance (this is a turn-based RPG battle system).
  • Full body must fit within the frame with generous margin — nothing cropped at edges.
  • Reframe fix for edge-cropped creatures: If a creature's anatomy is cut off by the frame edge, regenerate with aggressive center-framing: The creature occupies only the CENTER 70% of the frame, surrounded by clear empty background on all sides — nothing even close to any edge. Do NOT use outpainting/edits to extend — the edits endpoint degrades detail quality across the whole image even when only borders are masked. Always regenerate fresh.
  • Prompt boilerplate: In a natural combat-ready stance as if facing an opponent. Full body visible with generous margin on all sides, nothing cropped at edges. Centered, painterly dark-fantasy illustration, dramatic rim lighting with clear mid-key exposure, vivid readable colors, one single cohesive creature, no text, no props, no scenery. No floating or detached parts.
  • No repeated core motifs between different creature lines.
  • Stage-2 prompts stored in Image_Prompt column of codex/creatures.csv.
  • Approved art is locked — never regenerate or rewrite prompts for approved creatures without explicit instruction.
